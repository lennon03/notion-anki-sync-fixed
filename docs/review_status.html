What changed

Bugs that lost or garbled card content

  • Equations were not HTML-escaped: a<b in a formula swallowed the rest of the card.
  • Blocks indented under a paragraph, and the content of toggle headings, were downloaded and then dropped.
  • A table row's title went into the Front field as raw HTML.

Other fixes in the core and the add-on

  • Page ids are always lowercase, and arbitrary text is no longer taken for an id.
  • Cards written in a normal page that hold a page mention are checked again within the hour, and are dated by when their page was read.
  • Media is streamed to disk instead of held in memory; one failed file no longer aborts the sync.
  • An answer from Notion that is not JSON is retried. A long media file name keeps its extension.
  • A sync interval that is not a number no longer breaks profile opening or the Settings dialog. Page names in Settings are shown as plain text.

Improvements

  • Every data source of a database is read, not only the first.
  • A row moved to another table takes its cards along, if they are still in the old deck.
  • Row titles keep their formatting (bold, code, equations).
  • Rows of a table are downloaded three at a time.

Simplification

  • sync.py is split into cache, note_types, rows, fetch, media and apply. It still exports every name used elsewhere.
  • Dead code removed; helpers that existed two to four times now exist once (title extraction, plain text, the cloze and id patterns, note type creation, background collection changes, renewing the Notion sign-in).
  • The worker no longer calls the Notion client's private request method.

Hosted worker and site

  • The page picker renews an expired Notion sign-in, reads up to 5,000 search results and says when its list was cut.
  • No run can start while connecting or disconnecting AnkiWeb deletes the local collection.
  • The "nothing to do" check also notices edits that arrive from another device.
  • Sync options (sync_column, page_cards and others) can be set through PUT /config.
  • A long run log keeps its start and its end. The scheduler no longer logs a traceback every 30 seconds when a secret can't be read.
  • The exporter stops reading a table once it is over its row limit, and says so clearly when more than 12 tables are chosen.
  • The site answers "the sync worker can't be reached" instead of a 500 while the worker wakes.

Tests

  • Of 329 tests, 310 were kept, 7 merged and 12 deleted: duplicates, tests of private details, one that could not fail.
  • Four tests passed even with the behaviour they name broken. Three are fixed, one was the test that could not fail.
  • The 2,200-line test file is split into topical files; shared fakes are in tests/helpers.py.

What is left before main

1. Merge the stack into experimental

  1. Merge #3 to #10, squashing #10.
  2. Install the add-on built by CI in a real Anki and run one sync. Nothing in this review was run inside Anki, against the real Notion API or against AnkiWeb, and the split moved almost every function. The first sync downloads every row once.
  3. Merge #11, #14, #12, #15, #16, #17, #18.
  4. Decide on #13 (next section).

A merge into experimental deploys the worker and the site at once, without waiting for CI. Its current commit, to return to if needed, is ed5ba0b.

2. Look at these before they reach your cards

  • #13 Three downloads at a time. Tested with fakes only. If a real sync shows rate-limit warnings, take that part out; the rest of #13 stands without it.
  • #13 Formatted titles. The Front of existing cards changes where the title has bold, code or equations.
  • #12 The "nothing to do" check was tested against Anki's local sync server, not AnkiWeb. The worst case is one extra full read.
  • #12 Sync options have no form on the site yet; they can only be set through the API.
  • #17 and the page-picker line in #12 were typechecked, not seen in a browser.

3. Review points still open

  • C11 A page-card note with no cache entry is asked about once a day. Needs one request against a real workspace with an integration token.
  • I4 Whether renaming an inline table moves its page's edit time. Needs a test page where a table can be renamed.
  • W6 The whole collection is exported as a backup on every full read. No way was found to skip it and keep the backup guarantee.
  • B2 Deploys don't wait for CI. A setting in Railway and Vercel; worth turning on before the stack lands.

4. Not reviewed

  • The exporters' rendering code (html.ts, docx.ts).
  • settings_ui.py was skimmed for threading, parsing and markup, not read line by line.
