Notion Sync: what's new

Everything added on the experimental branch and how to use it. Notion stays the source of truth: all of this is controlled from your Notion tables, and the add-on only reads Notion.

Column names at a glance

Add these columns (properties) to a Notion table. Names are matched in Settings defaults and can be changed in the add-on config.

ColumnTypeWhat it does
AnkiCheckboxUnticked rows don't get a card.
Card typeSelect or textCloze, Overlapping (with options, see below) or Basic.

A table without a column simply behaves as before. Nothing is required.

Cloze cards

Write Anki's own cloze syntax in a row's title or page, for example The capital of France is {{c1::Paris}}. The row becomes a cloze card using a separate Notion Sync Cloze note type.

  • Cloze in the title: the title is the cloze text, the page goes to Back Extra.
  • Cloze in the page: title and page are the cloze text.
  • Or set the Card type column to Cloze. If the row contains no {{c1::...}}, it stays a normal card and you get a warning.
  • Switching a row between basic and cloze replaces its note in the same undo step. No duplicates.

Overlapping cloze

For text you recite line by line (quotes, poems). Set Card type to Overlapping. Each top-level block of the page (each list item too) is a line. Each card hides one line and shows the previous lines as cues. The back shows the full text.

Options go after the word in the same column:

  • Overlapping: all previous lines are shown, later lines are hidden.
  • Overlapping 2/1: show 2 previous lines and 1 following line as cues; every other line is hidden. Each number is 0 to 9.
  • Overlapping x2: 2 lines make one cloze (one card per 2 lines). Up to x20.
  • Overlapping 2/1 x2: both. The numbers then count groups, not lines.

An option the add-on does not understand (for example Overlapping 2) gives a warning and the row is made as plain Overlapping. Changing the option in Notion updates the card.

The hiding of lines uses the CSS :has() rule. Test it on your phone; on an old AnkiDroid or WebView without :has(), hidden lines would be visible. Anki's multi-id clozes ({{c1,2::...}}) were tried instead, but they only turn a line into [...], they cannot remove it, so the CSS stays.

Tags (strikethrough)

In the row's page, strike through a word to make it a tag. The struck text is removed from the card and becomes an Anki tag. Separate several tags with commas, or strike each one separately. Spaces become underscores, quotes are dropped, and :: makes a hierarchy. Every tag is put under Notion::, so physics becomes Notion::physics.

  • Only Notion:: tags are managed. Tags you add by hand in Anki are never removed.
  • Struck text inside code blocks and equations stays as it is.
  • There is no Tags column any more.

Cards in a normal page

The text of a configured page (not only its tables) can hold cards. They go in the page's own deck. Four formats, no setup:

Write thisYou get
### Question? or #### Question?, then the answer under itA card. The answer is everything up to the next heading or divider. A #### Hint inside it works as above, and a --- after the hint does not end the answer.
Q: question then A: answerA card. The answer runs until the next Q:, a heading, a divider or an empty line. Case does not matter, Question: and Answer: work. Shift+Enter between the two lines works too.
front :: back on one line (spaces around ::)A card, like Obsidian's Question::Answer.
A paragraph, list item, quote or callout with {{c1::cloze}}A cloze card, one per block. A heading with a cloze and no answer is a cloze card too.

Remember a list. If the answer of a heading or Q: is a numbered list (2 items or more), the card is an overlapping cloze like Cloze Overlapper: each card hides one item and shows the earlier ones. Write options after the question to change it, for example ### Steps [2/1 x2] (same options as the Overlapping Card type: [x2], [2/1], [overlap]). The options also work on a non-list answer, and each block is then a line.

  • Strikethrough tags and the Hint section work inside these cards too.
  • A heading with nothing under it is just a title, not a card.
  • Toggles are not read as cards. Content inside a toggle in an answer is shown as usual.
  • Each card is tied to its question's block, so editing the text updates the same note, and deleting the block removes the note.
  • Turn it off with "page_cards": false in the add-on config.

Choose which rows sync

Add an Anki checkbox column. Ticked rows (and every row in a table without the column) sync. Unticking a row that already has a card suspends it and tags it notion-sync::unchecked; it is not deleted. Tick it again to unsuspend. Cards you suspended yourself are never unsuspended.

Hint (adjacent note)

In the row's page, add a heading 4 called #### Hint. Everything under it becomes a collapsed Hint section at the end of the back. A divider (---) ends the hint; what follows the divider is back-of-card content again. Without a divider the hint runs to the end of the page.

  • The hint is part of the row, so there are no extra requests and no Context column any more.
  • For Overlapping cards the hint is not one of the lines.

Card styles

Settings has a new Cards section: pick Classic, T3 Ocean, Minimal or Custom (keep my CSS) and press Preview. Applying a style is one undo step called "Notion Sync: Card Style". The add-on no longer rewrites your note type's CSS on every sync, so hand edits in Anki now survive. Choose a preset only when you want to overwrite them.

Code highlighting and richer blocks

  • Code blocks keep their language and are coloured (comments, strings, numbers, keywords). Works offline, in light and dark, on every Anki client.
  • Synced block copies show their original's content. Columns render side by side and wrap on narrow screens.
  • Links to pages and child pages become links.
The first sync after updating re-reads every row once so existing cards get the new look. Nothing is deleted.

Renamed pages and tables

If you rename a Notion page or table, its synced cards move to the new deck, but only those still in the old deck. Cards you moved yourself stay. The old deck is left for you to delete.

Safer note type handling

The add-on remembers its note types by id, stored in the collection and shared through AnkiWeb. Renaming the note type or its fields in Anki no longer creates duplicates. New media files are copied into Anki's media folder during the Notion fetch.

Your own note type per table

After a first sync, Settings has a Note types section listing each table with a picker: Notion Sync Card (default) or one of your own note types. A type is offered when it is not a cloze type, has at least three fields, one of them named Source, and holds no notes with a Source yet. The first field gets the row title, the second the page (with its context), Source the row id, and any other field named like a Notion column gets that column's text. Saving is one undo step.

  • Only new rows use the chosen type. Cards already synced stay in their type and keep syncing; nothing is converted, moved or deleted, so switching never makes duplicates.
  • Cloze rows always use Notion Sync Cloze.
  • Your own notes in that type are left alone: only notes whose Source is a Notion row id count as synced.

Not built

  • Anki to Notion sync. Deliberately not built, since it would break "Notion is the source of truth". See docs/sync-direction.md.
